# Social images

> How to make a nerdos social post that's actually readable on a phone.
>
> The pieces are generated by `scripts/social-image.mjs` from a JSON config, using
> the real product assets — `public/BebasNeue.otf`, `public/mascot.png`, and the
> colour tokens parsed live out of `src/app/globals.css`. Nothing is redrawn by
> hand, so a brand change in the app flows into the next image you generate.

## Quick start

```bash
node scripts/social-image.mjs docs/social/answer-reveal-square.json
node scripts/social-image.mjs docs/social/answer-reveal-45.json

# override the output path
node scripts/social-image.mjs docs/social/answer-reveal-45.json --out ~/Desktop/post.png
```

Output goes to `out/` by default, which is already gitignored — generated images
never land in the public repo. Requires Chrome or Brave installed (the script
finds it; nothing to configure).

## The one rule that matters

**Size type from how big it lands on a phone, not from how it looks on your monitor.**

This is the mistake that ruins social pieces. A 1080px-wide image renders at
roughly 390pt on a phone — a **2.8× reduction**. A caption that looks
comfortable at 19px in your browser arrives at ~7pt in the feed, which is
unreadable. Every size in the generator was picked backwards from its on-screen
result:

| Element | Source size | On a phone | Notes |
|---|---|---|---|
| Headline | 104px | ~37pt | Bebas Neue, 2 lines max |
| Sub | 42px | ~15pt | the floor for body copy — don't go below |
| Card phrase | 74px | ~26pt | the thing people actually read |
| Card label | 31px | ~11pt | all-caps, wide tracking, decorative |
| Card footer | 38px | ~14pt | |

If a piece doesn't fit, **cut content — never shrink the type.** Shrinking the
type solves the layout and loses the reader, which defeats the whole exercise.

## Formats

| Format | Pixels (2× output) | Use it for | Card budget |
|---|---|---|---|
| `4:5` | 1080×1350 → 2160×2700 | **Default.** The tallest thing a phone feed will render, so it wins the most screen. | 2 cards |
| `1:1` | 1080×1080 → 2160×2160 | Square feeds, profile grids. | **1 card** |

Two cards do not fit in `1:1` at a readable type size — the generator refuses
rather than crops. That's the constraint, not a bug.

**There is no landscape format, on purpose.** A 1200×630 canvas is the widest
and shortest, so it gets scaled down hardest and shows the smallest type; that's
exactly the piece that turned out unreadable in a phone feed. At the type sizes
above the layout needs ~1250px of height, so 630px can't hold even one card. If
you need an OG / link-preview image, that's a different piece — headline only,
no cards — and it wants its own template rather than a squeezed version of this
one.

Both formats share one type scale, since everything scales off canvas width.

## Config reference

```jsonc
{
  "format": "4:5",                    // "4:5" | "1:1" | "16:9"  (default "4:5")
  "brand": "NERDOS.FUN",              // optional, defaults to NERDOS.FUN
  "headline": ["Now you always",      // array = explicit line breaks.
               "see the answer"],     //   Control them; don't let it wrap.
  "sub": "One or two lines. HTML entities are fine (&mdash;).",
  "headTop": 68,                      // optional top padding nudge
  "cards": [ /* see below */ ],
  "out": "out/piece.png"
}
```

### Card types

Both mirror the reveal cards in `src/app/grammar/game/over/page.tsx` and
`src/app/math/game/over/page.tsx` — same blank marker, same strike/highlight
treatment. A player should recognise the card instantly.

**Grammar** — `____` is the blank, replaced by the highlighted correct word:

```json
{ "type": "grammar", "phrase": "____ jacket is this?",
  "correct": "Whose", "picked": "Who&rsquo;s" }
```

**Math** — `shown` is struck through when it differs from `trueResult`:

```json
{ "type": "math", "left": 7, "op": "x", "right": 8,
  "shown": 54, "trueResult": 56, "picked": "&#10003;" }
```

`op` takes the server's stable values (`+ - x /`) and renders them as proper
glyphs (`+ − × ÷`), same as the game screen.

Omit `picked` on either card to get the timeout state ("You ran out of time").

## When it overflows

The script measures the rendered layout before screenshotting and fails loudly:

```
✗ Content overflows by 173px (ends at 1253, canvas is 1080).
```

This check exists because the failure is silent otherwise — the screenshot just
crops the bottom card off and looks fine until someone points it out. Estimating
box heights by hand doesn't work; the script reads the real geometry from the
browser.

Fixes, in order of preference:

1. Drop a card (`1:1` fits exactly one)
2. Shorten the sub to one line
3. Shorten the headline, or break it differently
4. Switch to `4:5`, which has ~270px more room

It also warns at under 40px of bottom margin — technically fits, looks cramped.

## Keeping it in sync with the app

- **Colours** are parsed from `globals.css` at generate time. Change a
  `--color-*` token and the next image picks it up. The script throws if
  `--color-ink`, `--color-muted`, `--color-teal` or `--color-red` disappear.
- **Font and mascot** are read from `public/`. Replace the files, and the
  images follow.
- **Card layout** is a hand-maintained copy of the two over-screen components.
  If you restyle the real reveal card, update `cardHtml()` in the script to
  match — that fidelity is the entire reason these pieces land.
